# PayPay CSV Optimizer for MoneyForward ME

PayPayとMoneyForward MEの履歴を自動で照合し、二重登録することなく、新しい取引だけをスムーズに家計簿へ登録できます。PayPayポイントで支払った分はPayPay残高とは別の口座として登録でき、ポイントと残高を併用した支払いも自動で分けて整理します。明細が多くても、上限に合わせて取り込み用ファイルを自動で分割します。

[公開アプリでPP2MFを使う](https://pp2mf.vercel.app/)

## 概要

PayPayから書き出した取引履歴を、併用払いの分割や支払い方法ごとの整理を行ったうえで、MoneyForward MEへ取り込めるファイルにします。過去の取り込みに重複や口座間違いが疑われる場合は、両サービスの明細を見比べて要確認候補を表示できます。

すべての処理はブラウザ内で行われ、取引履歴データをアプリケーションサーバーへ送信しません。

## 主な機能

- **PayPay支払い方法ごとの出力**: 「PayPay残高」「PayPayポイント」など、名前が「PayPay」で始まる支払い方法ごとにファイルを出力します。クレジットカードや銀行口座など、MoneyForward MEへ直接連携する支払い方法は対象外です。
- **既存取引の自動除外**: MoneyForward MEから書き出した入出金履歴を読み込むと、登録済みの明細を作成対象から自動で除外します。2種類の取引履歴はどちらを先に選んでも構いません。
- **口座別の残高管理**: MoneyForward MEに表示されている現在残高を支払い方法ごとに設定すると、未取り込み明細の増減額と、全件取り込み後の見込み残高を表示します。「MoneyForward MEで保存した」を押した分だけ現在残高を更新します。
- **重複登録・口座間違いの確認**: PayPay明細とMoneyForward ME明細を突き合わせ、完全一致しなかった要確認明細を表示します。
- **ファイル分割**: 1つの支払い方法で100件を超える取引がある場合、自動でファイルを100件ずつのチャンクに分割して出力します。
- **Web Share API対応**: 対応ブラウザでは生成したCSVファイルを共有できます。ファイル共有に対応していないブラウザでは通常のダウンロードとして動作します。
- **PWA共有ターゲット対応**: 対応するAndroid環境では、PayPayから書き出した取引履歴やMoneyForward MEから書き出した入出金履歴を、インストールしたアプリへ共有してそのまま入力できます。画面選択と共有のどちらでも、年ごとの入出金履歴を同じファイル名で重複させずに追加します。
- **プライバシー**: ファイルの処理はすべてクライアントサイドのJavaScriptで完結します。

入力CSVはUTF-8としての読み込みを試し、失敗した場合はShift_JISとして読み込みます。生成するCSVはBOM付きUTF-8です。

## 使い方

### MoneyForward MEに取り込むファイルを作る

1. **PayPayから書き出した取引履歴を選択（必須）**: PayPayアプリから書き出した取引履歴のCSVファイルを選択します。
2. **口座残高を設定（任意）**: 「作成したファイル」の口座名の横から、MoneyForward MEに表示されている現在残高を設定できます。未取り込み明細がある場合は、全件取り込み後の見込み残高を並べて表示します。
3. **MoneyForward MEから書き出した入出金履歴を選択（任意）**: 読み込むと、登録済みと判定された取引を作成対象から除外します。未選択の場合はPayPayの全取引を出力します。選んだファイルは端末内に保存されます。
4. **作成したファイルを取り込む**: 支払い方法・100件単位で分割されたファイルを、一覧から順にMoneyForward MEへ取り込みます。「MoneyForward MEで保存した」を押した明細は端末内へ記録され、次回以降の作成対象から除外されます。残高を設定している口座では、保存した明細の増減額も現在残高へ反映します。この記録と残高はMoneyForward ME本体と自動同期されません。

MoneyForward MEの入出金履歴CSVには口座残高が含まれないため、現在残高は手動で設定します。MoneyForward MEやPayPayで別の残高変動があった場合は、表示されている現在残高を設定し直してください。

### 重複登録・口座間違いを探す

「作成したファイル」の下にあるセクションを開くと利用できます。上で選んだ2種類の取引履歴をそのまま使用します。

1. **2種類の取引履歴を選択**: 正しい取引内容の基準となるPayPayの取引履歴と、確認したい期間を含むMoneyForward MEの入出金履歴を選択します。
2. **要確認明細を確認**: PayPay明細と完全一致しなかったMoneyForward ME明細について、内容と口座を確認します。
3. **MoneyForward MEで修正**: 不要な重複明細は削除し、必要な明細で口座だけが違う場合は口座を変更します。アプリが明細を自動変更することはありません。

照合にはPayPayとMoneyForward MEで共通する取引IDがないため、「日付」「金額」「内容」「口座」が一致する明細を同一とみなします。完全一致しなかったMoneyForward ME明細のうち、「日付」「金額」「内容」がPayPay側に存在するものだけを要確認明細として表示します。表示結果は削除や口座変更を確定するものではありません。必ず明細の内容を確認してから修正してください。

## 端末内のデータ保存

- 作業中のPayPayの取引履歴とMoneyForward MEの入出金履歴は、Share Targetによる画面遷移や再読み込み後も作業を続けられるようIndexedDBに保存します。ファイルは画面から明示的に削除するまで保持します。
- 「MoneyForward MEで保存した」の記録と、手動で設定した口座残高をブラウザの`localStorage`に保存します。
- MoneyForward MEの入出金履歴を追加・入れ替え・削除すると、「MoneyForward MEで保存した」の記録はリセットされます。口座残高は維持されます。
- CSVや明細情報をアプリケーションサーバーへ送信することはありません。

## 開発

### セットアップ

```bash
# 依存関係をインストール
npm install
```

### 開発サーバーの起動

```bash
npm run dev
```

### 品質チェック

```bash
npm test
npm run test:e2e
npm run typecheck
npm run lint
npm run build
```

E2E（画面操作とVisual Regression Test）はPlaywright公式Dockerイメージ内の
Linux/AMD64環境で実行します。事前にDockerを起動してください。基準画像を更新する場合は、表示差分を確認したうえで
`npm run test:vrt:update`を実行します。
